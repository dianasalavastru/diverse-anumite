# Project Context

## Project overview

This project is a real production website for an independent architect and designer.

The website will act primarily as:

- a professional portfolio
- a presentation of architectural and design services
- a presentation of technical services such as 3D scanning and drone photogrammetry
- a credibility and contact platform

The website is not an ecommerce product and does not require user accounts.

## Owner and work categories

The website represents one person whose work includes:

- architecture
- interior design
- architectural competitions
- personal architecture projects
- projects created during professional internships or employment at other architecture studios
- architectural rendering
- 3D laser scanning
- point cloud documentation
- drone photogrammetry

The website must clearly communicate the role and authorship of each project.

Projects may have different attribution types:

- personal project
- competition project
- collaboration
- internship or professional office work
- visualization only
- scanning or documentation service

## Primary user experience

The homepage should feel like an editorial architecture portfolio rather than a traditional corporate landing page.

The experience should be:

- visual
- calm
- premium
- minimal
- image-led
- typography-led
- highly curated

The homepage will use a long scrolling composition with multiple sections.

## Homepage structure

The expected homepage structure is:

1. Fixed navigation
2. Introductory visual gallery
3. Short studio or architect description
4. 3D scanning or point-cloud showcase
5. Drone and scanning services section
6. Project grid
7. Project carousel for one category
8. Project carousel for another category
9. Social media and contact area
10. Footer

The homepage should feel continuous and portfolio-like.

## Gallery interaction

The introductory gallery should be scrollable through approximately three visual states.

The desired interaction is inspired by the reference website included in the `references` folder.

Images should appear to float and reposition smoothly between states.

The design must not copy the reference website directly.

The reference is used only for:

- editorial feeling
- image layering
- oversized typography
- smooth floating movement
- generous whitespace
- restrained color usage

## Project detail page

Each project should have a dedicated detail page.

A project page may include:

- title
- project category
- year
- location
- authorship or role
- collaborators
- project description
- hero image
- image gallery
- drawings
- plans
- diagrams
- zoomable images
- related or next projects

## Navigation

The navigation should remain fixed.

Some navigation items will scroll to sections on the homepage.

Other items will open separate pages.

Likely navigation items:

- About
- Services
- Projects
- Contact
- Language selector

Projects and services may use dropdown navigation.

## Devices

Desktop is the primary presentation environment.

Mobile is also critical because users may arrive through Instagram, LinkedIn, or other social media.

The mobile version must preserve:

- the visual identity
- strong typography
- image dominance
- editorial rhythm
- motion character

It should not feel like a stripped-down fallback.

The design is not final.

Claude should challenge unclear decisions and identify missing requirements before implementation.

## Important constraints

- Do not copy the reference website.
- Do not start coding before the product and technical plan are approved.
- Motion must support the content and never reduce usability.
- The site must remain performant despite image-heavy content.
- The owner must eventually be able to add and edit projects without changing code.
